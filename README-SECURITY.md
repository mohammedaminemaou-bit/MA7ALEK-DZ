# MA7ALAK DZ — مراجعة الأمان وإعداد Supabase

## التعديلات التي أُجريت

- عزل بيانات التخزين المحلي حسب معرّف مستخدم Supabase (`shop-v1-user-<user-id>`) بدل استعمال مفتاح محلي واحد لكل الحسابات.
- منع رفع بيانات محلية قديمة تلقائيًا إلى حساب جديد. إذا وُجدت بيانات قديمة غير مرتبطة بحساب، تظهر مطالبة واضحة قبل نقلها.
- تحسين التحقق من رقم الهاتف وكلمة السر ورسائل أخطاء تسجيل الدخول.
- توضيح أن رقم الهاتف في النسخة الحالية هو معرّف للحساب فقط، وليس تحققًا عبر SMS.
- إضافة ملف `SECURITY_RLS.sql` لتطبيق سياسات وصول مقيّدة على جداول التطبيق.
- تعديل Service Worker ليعطي الأولوية للنسخة الأحدث من الملفات مع الاحتفاظ بالعمل دون اتصال عند تعذر الشبكة.

## تشغيل التطبيق

1. فك ضغط `ma7alak-app-secure.zip`.
2. ارفع الملفات إلى الاستضافة الحالية كما هي، أو شغّلها عبر خادم محلي/استضافة HTTPS. لا تفتح `index.html` مباشرة من `file://` لأن تسجيل الدخول وService Worker يحتاجان سياقًا آمنًا.
3. افتح التطبيق وسجّل الدخول. إذا كان لديك حساب قديم، جرّب الدخول قبل إنشاء حساب جديد.
4. إذا كانت هناك بيانات قديمة محفوظة على هذا الجهاز، وافق على نقلها فقط إذا كنت متأكدًا أنها تخص المحل الذي تسجّل الدخول إليه.

## تطبيق سياسات Supabase

1. افتح Supabase Dashboard ثم مشروع MA7ALAK DZ ثم **SQL Editor**.
2. راجع أسماء الجداول والأعمدة في `SECURITY_RLS.sql` وتأكد أن الجداول `shop_state`, `subscriptions`, `payments`, `app_config` موجودة، وأن عمود `user_id` نوعه مناسب لمعرف `auth.users.id`.
3. انسخ محتوى `SECURITY_RLS.sql` وشغّله. هذا الملف يحذف السياسات الحالية على هذه الجداول ثم ينشئ سياسات مالك صارمة؛ لا تشغّله قبل مراجعة أي سياسات/وظائف إدارية مخصصة عندك.
4. اختبر بحسابين مختلفين: يجب ألا يستطيع الحساب A قراءة أو تعديل صفوف الحساب B. اختبر كذلك تسجيل الدخول، البيع، إعادة تحميل الصفحة، وتسجيل الخروج.
5. افحص كل RPC إداري (`is_admin`, `admin_pending`, `admin_stats`, `admin_approve`, `admin_reject`) في Database → Functions. يجب أن تتحقق الوظائف من صلاحية المشرف داخل الخادم نفسه، لا من واجهة JavaScript، وأن تكون `SECURITY DEFINER` فقط عند الحاجة مع `search_path` آمن.

## ملاحظات أمنية مهمة قبل الإطلاق

- `SB_KEY` في الواجهة يجب أن يكون **publishable/anon key فقط**. لا تضع أبدًا `service_role` أو أي مفتاح سري في ملفات المتصفح.
- أسلوب تحويل الهاتف إلى بريد اصطناعي (`pXXXXXXXXX@users.example.com`) لا يثبت ملكية الهاتف ولا يدعم استعادة كلمة السر برسالة SMS. لا تعتبره مصادقة هاتفية حقيقية. قبل الإطلاق التجاري، خطط للانتقال إلى Supabase Phone OTP مع مزود SMS أو بريد إلكتروني موثّق.
- رمز القفل المحلي PIN وسيلة راحة فقط؛ لا يحمي البيانات من شخص يملك وصولًا تقنيًا إلى تخزين المتصفح. لا تحفظ كلمات السر داخل `localStorage`.
- التخزين المحلي ليس مشفرًا. استخدم قفل الجهاز ونسخًا احتياطية آمنة، ولا تعتبر التطبيق متوافقًا مع متطلبات حماية البيانات حتى تُراجع البنية كاملة.
- ملف SQL يضع قواعد وصول أساسية للجداول المذكورة، لكنه لا يثبت أن جميع وظائف الخادم آمنة. يجب اختبار RPC والاشتراكات والدفع يدويًا.

## الاختبارات المنفذة

انظر `TEST-REPORT.md` لنتائج فحص بنية الملفات واختبار صياغة JavaScript. اختبارات Supabase الحقيقية تتطلب تشغيلًا داخل مشروع Supabase فعلي بحسابين تجريبيين؛ لا يمكن تأكيدها من ملف ZIP وحده.

## تحسينات المزامنة في النسخة المعدّلة

- الحفظ المحلي يحدث أولاً، ثم تتم محاولة المزامنة السحابية؛ فشل الشبكة لا يمسح البيانات المحلية.
- فحص أخطاء Supabase في القراءة والرفع بدل اعتبار الطلب ناجحاً لمجرد اكتمال الوعد.
- أخذ نسخة ثابتة من البيانات قبل الرفع، ومقارنة عدّاد التعديلات بعد انتهاء الرفع، ثم جدولة رفع جديد إذا حدث تعديل أثناء العملية.
- تجاهل نتائج الطلبات القديمة إذا تغيّر الحساب/جلسة المزامنة.
- إعادة محاولة المزامنة بعد فشل مؤقت، وإظهار حالة أوضح عند انقطاع الإنترنت وعودته.
- تحديث إصدار Service Worker إلى `shop-v20` حتى لا يحتفظ المتصفح بكاش التطبيق القديم.

### حدود معروفة لم تُحلّ بمجرد تعديل الواجهة

جدول `shop_state` يخزن حالة المحل كلها داخل حقل JSON واحد. المزامنة والدمج من جهة العميل يقللان بعض التعارضات، لكنهما لا يضمنان عدم فقد التعديلات عند كتابة متزامنة تماماً من جهازين. للحماية التجارية القوية يلزم انتقال مرحلي إلى جداول منفصلة للعمليات (المبيعات، عناصر الفواتير، حركات المخزون، الدفعات) بمعرّفات فريدة، أو تنفيذ RPC معاملات على الخادم مع إصدار/قفل تفاؤلي. لا تنفّذ ترحيل قاعدة البيانات قبل أخذ نسخة احتياطية وفحص مخطط Supabase الحقيقي.

لم يتم الاتصال بمشروع Supabase أو تنفيذ SQL أو اختبار حسابات فعلية أثناء إعداد هذه الحزمة.
